## ADDED Requirements

### Requirement: 有序启动与交互式场景入口
框架 SHALL 提供可调用及命令行统一入口，严格依次读取数据库实例配置、读取插件配置并完成注册、读取 C++ 配置、完成框架及功能号 0 初始化、读取场景配置，最后提示用户选择场景。框架 SHALL 按模块职责完成各阶段，不从示例模块导入运行实现。

#### Scenario: 严格启动顺序
- **WHEN** 提供全部有效配置并启动入口
- **THEN** 全部实例解析先于插件注册，插件注册先于 frame 读取，native 初始化成功先于场景配置读取，所有场景校验成功才提示选择

#### Scenario: 前序阶段失败
- **WHEN** 实例解析、插件注册或 C++ 初始化失败
- **THEN** 不执行任何后续阶段或提示场景选择，返回非零结果，释放已经取得的资源且不输出连接凭据

### Requirement: 配置驱动注册与场景目录
框架 SHALL 根据插件 JSON 注册 Python 方法或 C++ 功能号，并根据场景目录 JSON 加载多个三级场景。相对场景文件路径 SHALL 以目录配置文件所在目录解析；空目录、重名场景、无效插件/实例和非法并发度 SHALL 在菜单出现前报错。

#### Scenario: 注册两种插件
- **WHEN** 插件配置含 Python 的模块方法引用和 native 功能号条目
- **THEN** 全部完成注册且不执行插件任务，未知类型、重复名和无效引用明确失败

#### Scenario: 初始化后场景加载失败
- **WHEN** C++ 已初始化但场景目录或场景内容无效
- **THEN** 不出现可执行菜单，关闭框架并释放主线程数据库资源

### Requirement: 会话选择执行与退出清理
入口 SHALL 接受编号或完整名称选择场景，逐次执行并输出独立报告，再次提示选择；非法输入 SHALL 不执行任务。同一会话 SHALL 只初始化一次 native，支持退出指令、输入结束和用户中断的资源清理。

#### Scenario: 重复选择和失败后继续
- **WHEN** 用户执行一个场景后再选择另一个场景，或先前任务失败
- **THEN** 场景顺序执行、报告分别保存、不会再次初始化 C++，任务失败后仍可选择；步骤保持串行且步骤内任务模式不变

#### Scenario: 非法选择和会话退出
- **WHEN** 用户输入空值、越界编号、未知名称后输入 q、exit、退出或结束输入
- **THEN** 非法输入只重新提示，退出不启动新场景，完成资源清理；中断亦等待在途任务清理并关闭框架

### Requirement: 数据库与C++初始化配置合并
统一入口 SHALL 移除 `init_param` 和 `profile` 参数。`instances.json` 每个实例条目 SHALL 同时保存 Python 数据库连接字段及 C++ 初始化所需的 `dbtype`、单一 driver 字符串、ODBC 扩展、XA 参数；入口按 `instances` 声明顺序选择第一条构造 `KcpsFrameInit` 参数。

#### Scenario: 单一实例配置初始化
- **WHEN** 实例配置包含数据库连接和 native 初始化字段，入口未收到实例选择参数
- **THEN** Python 数据库池与 C++ 初始化均使用同一实例条目，不读取或要求 init_param/profile

#### Scenario: 缺少 native 字段
- **WHEN** 被选实例缺少 C++ 初始化必需字段
- **THEN** 在调用 `KcpsFrameInit` 前报告字段错误并释放已创建的资源

### Requirement: C++框架生命周期与功能号调用
测试框架 SHALL 在显式初始化后加载平台对应的 kcps_frame 动态库，调用 `KcpsFrameInit` 一次，并提供带 JSON 参数和结构化结果的独立功能号 API；退出 SHALL 释放框架资源。

#### Scenario: 初始化并调用功能号
- **WHEN** 客户端提供 frame 配置、数据库初始化信息和 `func_id`/参数
- **THEN** 框架返回包含 func_id、worker_id、原始响应、结果码和错误信息的 `CallResult`

#### Scenario: 重复初始化和退出
- **WHEN** 多个调用方同时初始化或重复关闭
- **THEN** 初始化只执行一次，关闭操作幂等，非法生命周期调用得到明确异常

### Requirement: C++功能号并发
框架 SHALL 为活动线程分配唯一 worker id，并允许多个线程并发调用线程安全的 `KcpsFrameExecute`；单个线程的异常 SHALL 不破坏其他调用结果。

#### Scenario: 并发执行
- **WHEN** 场景中某个步骤以并行模式提交多个 C++ 功能号任务
- **THEN** 每个请求使用独立 worker id 并返回可按提交顺序关联的结果

### Requirement: GaussDB实例线程局部上下文
框架 SHALL 从指定配置读取全部实例连接信息，并按 `instid` 提供切换和 SQL 执行 API；实例选择和连接缓存 SHALL 是线程局部的。

#### Scenario: 切换实例
- **WHEN** 线程 A 选择 instid=a、线程 B 选择 instid=b
- **THEN** 两线程后续查询分别使用 a、b 的连接，互不覆盖

#### Scenario: 未知实例
- **WHEN** 请求不存在的 instid
- **THEN** API 在建立连接前抛出包含 instid 和可用实例的配置错误

### Requirement: 插件注册与场景编排
框架 SHALL 支持注册独立 Python 方法和 C++ 功能号插件，采用场景、步骤、任务三级模型。场景中的步骤 SHALL 只能按声明顺序串行执行；每个步骤 SHALL 包含一个或多个任务，步骤内任务 SHALL 支持串行和线程池并发两种模式。

#### Scenario: Python插件
- **WHEN** 注册一个接收 PluginContext 的 Python 方法并将其作为任务加入某个步骤
- **THEN** 执行器在该步骤开始后调用方法，并在对应步骤的任务结果中记录返回值

#### Scenario: 串行失败传播
- **WHEN** 串行步骤中的某个任务抛出异常
- **THEN** 本步骤剩余任务和后续步骤全部标记跳过，场景结果标记失败并保留具体任务异常

#### Scenario: 步骤内任务并发
- **WHEN** 一个步骤声明 parallel 并设置 max_workers
- **THEN** 本步骤任务允许同时运行且不超过配置并发度，其他步骤不得与本步骤重叠执行

#### Scenario: 步骤内任务串行
- **WHEN** 一个步骤声明 serial 或未指定 mode
- **THEN** 每个任务必须在前一个任务返回并完成清理后才开始，按声明顺序执行

### Requirement: 步骤完成屏障和任务超时
执行器 SHALL 等待当前步骤所有已启动任务及清理操作结束，且该步骤全部任务成功后才能启动下一步骤。步骤失败或超时时 SHALL 跳过后续步骤；超时 SHALL 取消未启动任务并等待已运行调用返回，不允许在后台任务仍运行时继续后续步骤。

#### Scenario: 较慢并发任务阻止下一步提前开始
- **WHEN** 当前步骤的快速任务已经结束而慢任务尚未结束
- **THEN** 下一步骤任何任务都不启动，直到慢任务也成功结束并完成清理

#### Scenario: 并发任务失败
- **WHEN** 某个并发任务失败且同一步骤其他任务仍在运行
- **THEN** 等待同一步骤其他任务结束，完整收集其结果，后续步骤全部标记跳过

#### Scenario: 步骤超时
- **WHEN** 步骤到达截止时间，包含已完成、未启动和仍运行的任务
- **THEN** 保留已完成结果，未启动任务取消，仍运行任务返回后标记其超时结果，不执行后续步骤且不报告强制终止成功

### Requirement: 任务上下文隔离和三级报告
每个任务 SHALL 获得独立参数副本和线程局部数据库选择，结束后 SHALL 清理自己的连接并恢复调用前上下文。结果 SHALL 按场景→步骤→任务嵌套，包含每层状态及耗时、任务返回值和异常，按声明顺序输出完整成功/失败/跳过记录。

#### Scenario: 同一插件在多个任务中使用不同参数和实例
- **WHEN** 同一步骤中多个任务调用相同插件，但指定不同 params 和 instid
- **THEN** 每个调用只看到自己的参数/实例，任务内修改参数不影响其他任务和原场景定义，线程复用不继承上个任务的数据库选择

#### Scenario: 并发完成顺序与声明顺序不同
- **WHEN** 后声明的任务先完成
- **THEN** 报告仍按步骤及任务声明顺序排列，结果及异常保持与原任务关联

### Requirement: 三级配置加载与旧模型拒绝
Python API、JSON 配置和 CLI SHALL 使用相同的场景→步骤→任务模型。执行前 SHALL 校验非空步骤/任务列表、名称唯一、任务插件存在和步骤并发参数合法；场景级并行参数与旧步骤直接引用插件格式 SHALL 被明确拒绝并提示迁移，不得静默执行。

#### Scenario: 加载混合任务模式场景
- **WHEN** 场景先包含串行任务步骤、再包含并发任务步骤
- **THEN** 两个步骤仍按顺序执行，各自遵循自己的任务模式，CLI 报告与 Python API 一致

#### Scenario: 旧场景并行配置
- **WHEN** JSON 顶层出现 mode/max_workers/timeout 或步骤直接配置 plugin
- **THEN** 在执行任何插件前报告迁移错误，提示把模式移至步骤、插件移至任务

### Requirement: 模块划分、代码注释与说明文档
新增框架 SHALL 按 `runtime`、`native`、`db`、`plugin`、`scenario`、`cli` 划分模块并保持职责边界；所有公开 API 和关键并发、资源、错误处理逻辑 SHALL 有详尽中文注释；项目 SHALL 提供与实现同步的中文说明文档。

#### Scenario: 代码审查注释完整
- **WHEN** 审查新增源文件及公开 API
- **THEN** 可从注释获知模块职责、参数/返回值、线程安全、native 内存和数据库连接生命周期，关键分支均有业务原因说明

#### Scenario: 按文档创建插件和场景
- **WHEN** 开发者只阅读 README、API、配置和插件/场景指南
- **THEN** 能按照示例完成环境检查、注册 Python/C++ 任务、选择 instid、运行包含串行/并发任务步骤的场景并解释失败结果

#### Scenario: 模块边界验证
- **WHEN** 执行静态检查或模块依赖检查
- **THEN** 模块目录和导入关系符合设计，CLI 不承载 native/db 实现，native/db 不依赖场景编排层

### Requirement: 独立依赖目录与完整离线交付
框架 SHALL 将启用功能所需的第三方组件及全部传递依赖提前下载到独立的 `dependencies/` 目录，与框架源码分离并随框架交付。交付 SHALL 包含运行、测试/检查和安装所需组件的精确版本、来源、用途、相对路径、SHA-256 和许可证清单。Python 解释器、系统基础环境及许可证前置条件 SHALL 明确记录。

#### Scenario: 依赖准备完成
- **WHEN** 针对目标环境和选定驱动完成联网依赖准备
- **THEN** 对应目录包含锁定清单列出的实际依赖文件及其传递依赖，文件校验通过，仅提供下载脚本或依赖名称不视为交付完成

#### Scenario: 需要原生驱动
- **WHEN** 选定适配器依赖 libpq、ODBC 驱动或管理器等原生运行库
- **THEN** 交付目录包含所需可分发组件以及经授权提供的本地驱动安装包，清单区分 wheel 内置依赖与独立安装依赖

### Requirement: 平台适配与禁止联网补包
依赖包 SHALL 按操作系统、CPU 架构、Python 版本及 ABI 区分；离线安装 SHALL 在独立虚拟环境中仅使用指定本地目录的锁定依赖，安装和运行 SHALL 不自动访问公网包源或使用缓存掩盖缺包。框架 SHALL 在安装前检查目标兼容性及文件完整性。

#### Scenario: 无缓存环境离线安装运行
- **WHEN** 在匹配的目标机器上提供完整依赖目录，创建全新虚拟环境并禁用外部包源访问和下载缓存
- **THEN** 安装及依赖一致性检查成功，关键模块导入、CLI dry-run 和 mock 测试通过，运行无需下载第三方组件

#### Scenario: 文件缺失或损坏
- **WHEN** 本地目录缺少任一所需依赖或其 SHA-256 与清单不一致
- **THEN** 安装失败并报告组件与本地路径，不访问远程包源补包，也不将环境标记为安装成功

#### Scenario: 平台或ABI不匹配
- **WHEN** 目标环境与制品声明的操作系统、架构、Python 版本或 ABI 不兼容
- **THEN** 安装在使用不兼容组件前失败，并说明当前环境及所需依赖包类型

#### Scenario: 离线连接测试数据库
- **WHEN** 第三方依赖已离线安装，目标机器可连接指定的测试 GaussDB 且原生库、配置和许可证齐备
- **THEN** 数据库和 C++ 功能号调用无需访问公网包源；数据库连接失败须与依赖安装错误分开报告

### Requirement: 离线依赖维护文档
框架 SHALL 提供中文离线部署说明以及有详尽中文注释的依赖准备、校验和安装工具，说明目录结构、支持的平台组合、驱动选择、环境前提、升级回退及故障排查。

#### Scenario: 依赖升级交付
- **WHEN** 升级任一第三方组件
- **THEN** 同步更新锁定清单、实际文件、校验信息和文档，并重新执行目标环境离线验证后才能将对应任务标记完成
