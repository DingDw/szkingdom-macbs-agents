# 新增资产单元分算积数、主资金单元累计计息模式

## 背景与原因

需求编号：FS-CBS-21645。现有模式 `'0'` 先汇总余额再计算积数，会使同一资金账号下不同资产单元的正负余额相互抵销；模式 `'1'` 虽独立计算，但积数、利息和结息结果保留在各资产单元。需要新增一种模式，在计算当日积数时保留资产单元边界，最终仍由主资金单元承载累计积数和应收、应付利息。

## 变更内容

- 为参数 `67042` 新增值 `'2'`，含义为“各资产单元分算当日积数，汇总到主资金单元累计计息”；保留值 `'0'`、`'1'` 和默认值 `'0'`。
- 用户已确认：所有资产单元均参与，包括主资金单元自身。按资金账号、币种、资产单元和计息日期分别计算当日利息积数、罚息积数，分类后分别累计，禁止先合并不同资产单元的正负余额。
- 将本次新增利息积数、罚息积数分别加到主资金单元已有累计积数上，再一次性计算主资金单元应收利息、应付利息；子资产单元只提供计算输入，不生成这四类结果簿记。
- 模式2由专用 `CalcDailyMainAwardamt()` 完成逐单元分算及首次结息时的主单元累计，四个计算入口直接调用，再直接调用 `CalcDailyMainInterest()` 计算主单元利息；`CalcAwardamt()`、`CalcAwardintr()` 保留模式0/1原有算法。
- 模式2统一使用 `m_mapFundunitSrcData` 按来源单元保存输入、六类历史索引、状态及日间调整；各入口完成全部Cache后统一确定主单元，仅归集账号状态和调整，余额、未交收及历史索引保持独立，不通过Check补全。实库转账始终按所属单元缓存，账号级extinfo明确绑定主单元，不兼容未指定资金单元的转账记录。
- 新模式结息流水和利息税归属主资金单元；不使用模式 `'1'` 的逐单元利息取整及尾差分配流程。
- 统一日终积数计算、单客户试算、单客户结息、批量结息及日终任务结息的新模式语义，沿用原功能号、阶段、分段、恢复及写库边界。
- 模式2暂不记录 node_fundintrdetail：现表仅有 todayawardamt，无法完整表达同日分别产生的利息、罚息积数；不扩表，保留明确业务注释。原模式0明细处理、模式1屏蔽行为保持不变。
- 单客户计算和单客户结息在取参阶段读取实际计息模式：仅模式1接受非空且非`0`的extfundunit，其他模式直接提示“当前模式不支持资金单元级别的单客户结息”；未传、空值或`0`均不指定资金单元。
- 在日终 Gauss 增量脚本中扩展参数定义的可选值和说明，注释标注 FS-CBS-21645，不自动启用新模式。

## 能力范围

### 新增能力

- `fundunit-daily-main-interest`：独立计算各资产单元当日利息、罚息积数，统一累计并结息到主资金单元，涵盖参数、数据归集、计算、结果归属和重做一致性。

### 修改既有能力

无。现有主规格未覆盖本模块的该计息能力。

## 影响范围

- `macbs-base`：`macbs_dict.h` 计息模式宏；`cbs_interest_deal` 模块本地基类、数据结构，以及功能号 `627012`、`627013`、`627014`、`627017`、`627020` 的参数分支、缓存、计算和结果处理。
- `macbs-service`：`database/script/patch/gauss/fs_cbs/fs_cbs_comm/2.data/sys_param_define.sql` 中参数 `67042` 定义；不修改全量脚本、模型 JSON、历史表、日切或归档配置。
- 沿用日终三段式积数、任务结息，以及日间三段式批量结息和单客户试算、结息入口；不增加导出入口，不修改日间清算独立模块。
- `Node_intradjustlog` 仅沿用日间批量、单客户的原有消费路径；日终积数及任务结息不新增调整流水加载、积数追加或调整账号分段来源。
- 仅处理本模式正确运行必需的分支适配，例如单客户未交收金额归集、入参转账归属和主单元扣税；现有模式 `'1'` 的尾差等独立问题不作为本需求的通用修复范围。
- 按用户补充要求，不新增子资产单元历史累计积数、应收应付及未归本利息的存量检查；历史结果只读取主资金单元，子单元历史记录不自动迁移或合并。
