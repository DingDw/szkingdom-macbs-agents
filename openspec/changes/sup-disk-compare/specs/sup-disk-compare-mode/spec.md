## Purpose

在现有 SUP 全量文件分析流程中提供可配置的磁盘对比模式，保证旧模式继续运行，并将文件导入、源数据持久化、文件核对与流程清理组织为可重做的依赖链，使查询端只展示本轮已完整完成的分析结果。

## ADDED Requirements

### Requirement: 流程参数选择分析模式
流程 `flowchartid=9` 及其运行实例 MUST 支持 `supmode=1/2`、`checkpartids` 和 `checktimeout`。缺失 `supmode` MUST 按 `1` 执行原 `sup-wzrsjfx` 方案；模式 `2` MUST 使用非空逗号分隔的分区列表，规范化空格和重复分区，并采用正整数秒的 `checktimeout` 限制整个核对任务总耗时，缺失时为 `600`。非法模式、分区空项、通配符、未知分区及非法超时 MUST 报错。模式 `1` 不启用核对参数。

流程启动查询 MUST 携带模板 `comm_flowchartinfo.params`，使真正初始化入口 `DayInitHandler.dayInit()` 能通过原有对象复制、实例落库及任务参数合并继承配置。未显式覆盖时，不得因查询遗漏字段导致模式2退回模式1。修复不自动重写已有实例，批次重置后重新初始化才生成新的参数快照。

#### Scenario: 模板模式2参数带入实际流程
- **WHEN** 模板 params 配置合法的 supmode=2、checkpartids 和 checktimeout JSON，启动入口未覆盖参数
- **THEN** 实际流程实例保存模板 params，准备任务取得对应参数并生成模式2核对任务，不因启动查询遗漏参数退回默认模式

启动请求的 NULL、空串或纯空白 params MUST NOT 使最终实例丢失模板参数。真正初始化入口 `DayInitHandler.dayInit()` 在入参参数为空时 MUST 按输入模板流程编号补取模板 params，再将最终实例参数合并到任务参数。非空启动参数按既有覆盖规则优先。任务参数合并 MUST 先于流程缓存构建，使缓存和落库参数一致。

#### Scenario: 启动请求没有参数
- **WHEN** 模板9配置模式2 JSON，但启动请求的params为NULL、空串或纯空白
- **THEN** 保留模板参数，实际实例及其任务继承模式2配置，不被空值清掉

#### Scenario: 直接调用真正初始化入口但入参遗漏参数
- **WHEN** DayInitHandler.dayInit收到模板流程编号9及不含params的流程对象
- **THEN** 在生成实际编号前补取模板参数，最终实例和任务均使用补取值；若模板也未配置，则继续原默认模式

#### Scenario: 缓存参数与落库一致
- **WHEN** 初始化按最终实例JSON合并任务参数
- **THEN** 合并后再生成流程缓存，任务节点与落库记录包含相同的模式、分区和超时参数

#### Scenario: 修复后重新初始化已有批次
- **WHEN** 修复前已生成缺少参数的实例，按正常批次重置流程重新初始化
- **THEN** 新实例继承本次模板参数，旧实例不会由本修复自动补写

#### Scenario: 升级后保留旧配置
- **WHEN** 原流程未配置 `supmode`
- **THEN** 继续执行原导入过滤、忽略判断和丢弃结果持久化，不生成核对任务

#### Scenario: 指定分区并使用默认超时
- **WHEN** 模式 `2` 参数为 `checkpartids=1, 2,1` 且未配置超时
- **THEN** 实际检查分区集合为 `1,2`，超时按 `600` 秒处理

#### Scenario: 新模式参数非法
- **WHEN** 模式 `2` 缺少分区、含空分区或未知分区，或超时为非整数、零或负数
- **THEN** 在生成可执行任务前报告明确配置错误

#### Scenario: 本轮执行中修改流程参数
- **WHEN** 准备已生成任务，随后修改流程模板的模式、分区或超时
- **THEN** 本轮任务继续使用准备时保存的同一组参数，重新准备后才使用新参数

### Requirement: 每个文件核对依赖本文件源数据持久化
模式 `2` MUST 为每个启用的 `intfid+fileid` 生成一个核对任务，其前置为本文件持久化任务，运行在可访问同一 SUP 全量源 MemDB 的执行上下文中。源表持久化完成后 MUST 保留该内存数据直至核对完成。任务超时 MUST 使用 `checktimeout` 控制整次执行总耗时，包含清理、轮询、磁盘读取、计算及写入，不得在阶段切换后重置计时。采用简单的经过时间检查，允许阻塞调用返回后才发现超时，不要求精确到秒的强制中断。

#### Scenario: 两个文件分别完成持久化
- **WHEN** 文件 A 已持久化而文件 B 尚未完成
- **THEN** 文件 A 的核对在其前置满足后可执行；文件 B 的核对不能越过本文件持久化前置

#### Scenario: 文件持久化失败
- **WHEN** 某文件源数据持久化失败
- **THEN** 不执行该文件后续核对，不释放其尚需恢复的 SUP 执行上下文

#### Scenario: 轮询和后续计算共享预算
- **WHEN** 核对等待状态已消耗部分 `checktimeout` 时间
- **THEN** 磁盘读取和结果提交继续累计本次任务耗时；后续检查发现总耗时达到超时阈值时，任务报错退出，不发布成功结果

#### Scenario: 阻塞调用返回后发现超时
- **WHEN** 某次磁盘调用跨过总超时阈值才返回
- **THEN** 允许在返回后的检查点判定任务超时，不要求精准中断该调用；不继续后续业务处理或发布成功，已经提交的数据仍受失败查询门禁约束

### Requirement: 模式 2 导入保留全量记录且不执行分析规则
模式 `2` 的 SUP 文件导入 MUST 跳过全部业务数据过滤和忽略规则检查，包括过滤配置读取后的不支持方式检查、预过滤、正式过滤及业务主键过滤；不得读取、预解析或执行忽略规则，不得清理、生成或写入 `sup_filedropdata`。所有可解析源记录及原始整数 `id` MUST 保留，文件解析与字段转换错误 MUST 正常报错。模式 `1` 及普通业务实例行为 MUST 保持。

#### Scenario: 配置旧模式不支持的过滤方式
- **WHEN** 模式 `2` 文件配置含原 `1/6/4` 等过滤方式
- **THEN** 不因过滤方式校验失败，按全量源记录导入，导入阶段不生成丢弃记录

#### Scenario: 忽略规则非法但正在导入
- **WHEN** 模式 `2` 存在非法忽略表达式，当前执行文件导入
- **THEN** 导入阶段不加载或校验该表达式，表达式错误由后续核对负责处理

#### Scenario: 源记录格式错误
- **WHEN** 全量文件记录无法解析或原始 `id` 不满足要求
- **THEN** 文件导入失败，不将其伪装为“跳过过滤后导入成功”

### Requirement: 模式 2 文件持久化仅生成源表配置
模式 `2` 文件持久化 MUST 仅生成当前源表的持久化配置，不生成 `sup_filedropdata` 配置，并移除同一配置组中旧模式遗留的丢弃表配置。模式 `1` MUST 保持源表和丢弃表一起持久化。SUP 文件日志的持久化标志仍只表示本文件对应持久化完成，不能替代核对完成状态。

#### Scenario: 从模式 1 切换为模式 2
- **WHEN** 当前文件配置组已有源表与丢弃表两条配置，重新按模式 `2` 准备持久化
- **THEN** 最终只保留本轮源表配置，旧丢弃结果不会被源数据持久化任务重新写回

### Requirement: 重做与清理覆盖核对任务
准备重做 MUST 删除并重建本流程生成的任务及结果，覆盖旧核对任务；切回模式 `1` 时仍须删除模式 `2` 残留核对任务。模式 `2` 正常清理 MUST 等待本轮所有文件持久化和核对任务成功，包括尚未激活的任务，并在失败时保留可恢复执行上下文。

#### Scenario: 核对尚未激活或已失败
- **WHEN** 所有源表已持久化，但至少一个核对未激活、等待中或失败
- **THEN** 流程不执行成功清理，不释放 SUP 节点映射

#### Scenario: 核对失败不自动重新调度
- **WHEN** 核对检测到业务持久化状态 3 并退出，业务侧稍后恢复成功
- **THEN** 流程引擎不自动重试或恢复该核对任务，保留失败状态及执行上下文，等待人工重新触发

#### Scenario: 模式切换后重新准备
- **WHEN** 模式 `2` 已生成核对任务，随后切为 `1` 并重做准备
- **THEN** 旧核对任务及其结果被移除，新一轮只包含原模式任务，旧完成状态不能使新一轮提前完成

#### Scenario: 空启用文件清单
- **WHEN** 准备时无启用文件
- **THEN** 删除本流程旧动态任务，不新增加载、导入、持久化或核对任务，沿用空流程清理约定

### Requirement: 查询模式 2 结果必须核对本轮完成状态
模式 `2` 查询 MUST 在当前业务日、当前流程和当前文件对应的本轮核对成功、结果已提交后才返回分析结果；仅源表持久化标志成功不得开放结果。核对失败、运行中或单独重做时不得回退返回旧成功结果。原查询字段和忽略标志语义 MUST 保持。

#### Scenario: 源表已提交但核对仍轮询
- **WHEN** 文件日志显示持久化成功，而本轮核对尚未完成
- **THEN** 查询明确返回尚未就绪，不将空丢弃表解释为全部已导入

#### Scenario: 单独重做核对
- **WHEN** 上轮流程曾成功，当前文件开始重新核对
- **THEN** 旧结果暂不可作为本轮成功结果查询，直至本次核对成功

#### Scenario: 成功清理已释放节点
- **WHEN** 本轮核对成功并已清理临时配置及节点映射
- **THEN** 仍可根据本轮任务实例关联从 SUP 磁盘查询完整结果
