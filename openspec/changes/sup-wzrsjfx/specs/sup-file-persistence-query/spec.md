## Purpose

将当天全量文件记录及未导入分析结果按文件可靠保存到 SUP 磁盘库，并通过当前清算业务日期、文件清单和完成状态提供一致的查询结果，使计算节点释放后仍可追踪当天未导入记录及其过滤原因和忽略状态。

## ADDED Requirements

### Requirement: SUP 仅提供当天数据
系统 MUST 将 SUP 全量数据和分析结果限定为当前清算业务日期的数据，本期不提供历史数据查询、历史保留或归档能力。当前日期必须取清算业务日期；丢弃记录中的业务日期及流程、文件日志仍用于核验当天结果，不因取消历史功能而省略。

#### Scenario: 已有过去日期的成功记录
- **WHEN** 存在过去业务日期的流程或文件成功日志，用户请求该过去日期的数据
- **THEN** 拒绝查询并提示 SUP 仅支持当前业务日期，不能以旧成功日志读取当天数据冒充历史结果

#### Scenario: 当天业务日期尚未完成处理
- **WHEN** 清算业务日期已变化，但新业务日期的全量导入流程或所选文件持久化尚未完成
- **THEN** 不开放查询，前一业务日期的成功状态不能用于放行

### Requirement: 单文件持久化包含全量和分析记录
系统 MUST 为启用文件建立持久化任务，将当天全量记录及对应丢弃记录持久化到 SUP 磁盘库；持久化分组采用 `sup_${fileid}` 约定。当前启用范围仅为 `SHJS/SH_JSMX01`，对应 `sup_SH_JSMX01` 和源表 `sh_jsmx`，本期不要求支持或验收 `SH_JSMX02/03` 的共表批次隔离及跨接口同名分组冲突处理。不要求为了历史存储给源接口表增加业务日期字段或建立历史表。

#### Scenario: 丢弃记录按文件重新持久化
- **WHEN** 当前文件全量导入重新生成丢弃结果并执行持久化
- **THEN** 沿用当前持久化配置，按本次 `intfid+fileid+busidate` 清空磁盘丢弃旧结果后写入本次结果，不删除其他接口、文件或业务日期的记录

#### Scenario: 空文件持久化
- **WHEN** 合法空文件导入成功
- **THEN** 持久化建立可查询的空结果，并清理同范围重试遗留记录后允许标记成功

### Requirement: 持久化前处理按参数动态建表
系统 MUST 在启用 dynamic_create_table 时，仅对本次持久化配置 globaldeletesql 为空、纯空白或去除前导空白后以 truncate 开头（大小写不敏感）的表执行动态重建；delete 开头及其他非空前缀不得触发建表或删表。允许重建的表 MUST 使用 DROP TABLE IF EXISTS 后 CREATE TABLE，不查询表是否存在，不保留已有旧结构。字段和主键依据对应 MemdbManager，保留原有记录身份，不补造 id。未启用参数时保持既有前处理行为。

#### Scenario: 本次目标表尚未创建
- **WHEN** 文件已成功导入，本次目标表尚不存在、删除条件为空或 truncate 开头，且前处理启用了动态建表参数
- **THEN** 系统执行 DROP TABLE IF EXISTS 后依据对应表结构创建目标表，前处理成功后才执行持久化，并保留源记录的 `id` 数值

#### Scenario: 动态建表失败
- **WHEN** 本次目标表删除或重新创建失败
- **THEN** 前处理和文件持久化任务报告失败，不继续执行后续数据写入，也不标记文件持久化完成

#### Scenario: 既有持久化调用未启用建表参数
- **WHEN** 既有流程未传入或未启用新增动态建表参数
- **THEN** 系统维持原前处理行为，不因 SUP 功能引入额外的自动建表行为

### Requirement: 持久化编排透传任务参数并沿用现有调用行为
`supFilePersist` BEX 流程任务 MUST 沿用系统现有请求组装方式，将任务上的参数透传给 C++ 功能号，在本次 SUP 实例、计算节点和文件范围内依次调用持久化前处理 `600003` 和持久化 `600001`，依据现有调用结果确认前者成功后才执行后者。调用结果、异常、超时及重做处理 MUST 与系统当前行为一致，不新增 Java 侧远端状态轮询、C++ 停止确认或超时后的重试准入判断；不能仅因调用已发起就宣告成功。

#### Scenario: 任务参数透传
- **WHEN** Java 文件持久化任务调用 C++ 前处理或持久化功能号
- **THEN** 按现有请求约定透传任务上的参数，SUP 参数使用任务配置值，既有业务及运行控制参数保持原有传递行为

#### Scenario: 持久化调用超时
- **WHEN** Java 调用 C++ 持久化触发系统既有超时处理
- **THEN** 沿用现有调用与任务处理机制，不由 SUP Java 编排新增远端是否仍在运行或何时允许重试的判断

#### Scenario: 前处理失败阻断持久化
- **WHEN** 前处理调用异常或返回失败
- **THEN** 文件任务失败，不再调用持久化功能，文件完成标志不得置为 `1`

#### Scenario: 远端持久化失败
- **WHEN** 前处理成功但后续持久化调用异常或返回失败
- **THEN** 文件任务按现有失败机制向流程引擎返回失败，不将文件标记为持久化完成

### Requirement: 文件完成标志反映完整持久化结果
系统 MUST 为 `comm_if_file_log.persiststatus` 提供默认值 `0`，仅在对应文件全量数据和丢弃数据均成功持久化后更新为 `1`；开始重做前必须使旧的成功标志失效，失败后不得返回误导性的成功状态。

#### Scenario: 只完成全量表写入
- **WHEN** 全量表写入成功但丢弃表写入失败
- **THEN** 文件仍为未完成，任务报告失败，用户不能通过查询得到该文件的完整分析结果

#### Scenario: 文件持久化重试
- **WHEN** 失败文件通过系统现有重做机制重新执行持久化
- **THEN** 按同一文件和日期幂等替换或补全结果，不累积重复记录，所有写入成功后才标记完成

### Requirement: 查询校验当前业务日期及流程完成
系统 MUST 将 `busidate` 作为必填查询条件，先校验其等于当前清算业务日期，再核对当天文件全量导入流程已成功完成且所选文件已持久化；非当天日期、缺少当天完成记录、失败或执行中时拒绝查询并说明原因。本期不查询历史流程状态以开放历史数据。

#### Scenario: 绕过页面直接调用接口
- **WHEN** 用户直接请求一个未完成业务日期的查询接口
- **THEN** 服务端拒绝查询并返回流程未完成的明确提示

#### Scenario: 非当天日期请求
- **WHEN** 用户请求过去或未来业务日期
- **THEN** 服务端拒绝查询并提示“SUP仅支持查询当前业务日期数据”

### Requirement: 文件树筛选兼容旧调用
`commIfIntfQueryAll` MUST 接受可选入参 `supflag`；传入 `1` 时仅返回启用全量导入的文件及其非空接口分组，未传入时保持原有文件树筛选及排序行为。

#### Scenario: 旧页面调用
- **WHEN** 既有页面不传 `supflag` 查询文件树
- **THEN** 返回结果保持既有接口约定和筛选行为

#### Scenario: SUP 页面调用
- **WHEN** 未导入数据分析页面传入 `supflag=1`
- **THEN** 文件树只包含启用文件，过滤后没有文件的接口分组不显示

### Requirement: SUP 磁盘查询返回记录和分析属性
系统 MUST 提供 `querySupDiskDBByTableName`，按当前业务日期、接口、文件及分页条件读取 SUP 磁盘数据，返回源字段、记录标识、是否未导入、丢弃原因及忽略标志。当前通过 `SHJS/SH_JSMX01` 文件配置解析源表 `sh_jsmx`，以源 `id` 与已限定接口、文件和当天日期的丢弃记录关联，不要求源表包含 `intfid/fileid/busidate`，也不增加针对未启用的 `SH_JSMX02/03` 的批次筛选适配。选择“只查看未导入数据”时仅返回存在丢弃记录的源记录，未选择时返回全部源记录；数据和统计总数必须使用一致的关联与过滤条件。

#### Scenario: 当前仅启用第一批次文件
- **WHEN** 当前仅启用 `SHJS/SH_JSMX01`，查询其当天持久化结果
- **THEN** 按文件配置读取 SUP 库的 `sh_jsmx` 并关联该文件当天的丢弃记录，不要求源表具有业务日期字段，也不要求为未启用的 `SH_JSMX02/03` 增加批次隔离处理

#### Scenario: 查询全量记录
- **WHEN** 一个文件含有通过过滤、未忽略丢弃、允许忽略丢弃三类记录，用户未选择只看未导入
- **THEN** 返回三类全部记录，通过过滤的记录不伪造丢弃原因

#### Scenario: 查询命中规则编号
- **WHEN** 查询结果包含已持久化的丢弃记录
- **THEN** 返回的 `dropruleid` 与命中的原始 `comm_filefilterrules.ruleid` 一致，不转换为过滤方式编码；`dropruledesc` 展示已持久化的该记录具体拒绝原因，不替换为配置中的规则描述

#### Scenario: 仅查询未导入记录
- **WHEN** 用户选择只查看未导入数据
- **THEN** 返回两类丢弃记录及其忽略标志，排除通过过滤的记录，分页总数等于全部匹配的丢弃记录数

#### Scenario: 非法表名或跨文件请求
- **WHEN** 请求表名与启用文件配置不匹配，或请求未授权文件的数据
- **THEN** 系统拒绝请求，不访问任意表或拼接执行任意条件

### Requirement: 页面采用统一业务日期和磁盘查询
系统 MUST 提供“未导入数据分析”页面，参考历史接口及登记公司数据查询的布局，删除“查询历史数据”条件，增加“只查看未导入数据”条件；页面业务日期限定为当前清算业务日期，使用左侧文件清单及右侧数据结果，并始终查询磁盘结果。

#### Scenario: 当前业务日期变化
- **WHEN** 当前清算业务日期发生变化
- **THEN** 页面清空旧结果并重新判断当天流程状态，不提供历史日期浏览

#### Scenario: 计算节点已释放
- **WHEN** 流程完成且 SUP 计算节点映射已被清理
- **THEN** 页面仍可从磁盘库查询成功持久化的数据

#### Scenario: 页面字段和分页响应
- **WHEN** 用户在菜单 `606049900` 的未导入数据分析页面选择文件
- **THEN** 页面通过既有 `getColumnNameList` 获取字段，通过 SUP 查询接口取得统一分页响应；业务日期只读，加载或切换文件时刷新日期，并定期检查日期变化清空旧结果

#### Scenario: 业务域权限
- **WHEN** 用户请求当前实际业务域、分区的 SUP 实例数据
- **THEN** 服务端校验实际业务域和分区权限；分区为 `*` 时要求全部源实例分区授权，不校验样例固定值，不通过修改请求表名绕过权限


### Requirement: 持久化配置使用当前任务实例的数据源名称
系统 MUST 使用当前 Java 任务参数 instid 查询 COMM 库 comm_instance，取 instname 写入源表及丢弃表两条持久化配置的 dbname，不得硬编码 sup 或直接采用任务传入的 instname。实例查询及配置替换处于同一事务；查询无结果或名称为空时失败，不写入无效配置。

#### Scenario: 实例名称不是 sup
- **WHEN** 当前任务 instid 对应实例的 instname 为其他实际名称，即使任务参数 instname 不同
- **THEN** 两条新增配置的 dbname 均为 comm_instance 查询得到的实际名称，C++ 调用仍沿用任务参数透传

#### Scenario: 实例不存在或名称为空
- **WHEN** 当前任务 instid 没有对应实例，或实例未配置 instname
- **THEN** 配置准备失败，不删除已有配置，不调用后续持久化功能号

### Requirement: 动态重建区分整表清理与按条件删除
系统 MUST 根据当前配置的 globaldeletesql 选择重建范围，已存在表同样按最新模型重建；按条件 delete 的表由既有部署维护结构。

#### Scenario: 已有源表结构过旧
- **WHEN** 源表已经存在，配置删除条件为空或以 truncate 开头，且启用动态建表
- **THEN** 删除旧表后按当前 MemdbManager 字段及主键重建，再持久化当前内存记录，不因表已存在而保留旧字段结构

#### Scenario: 丢弃表按条件删除
- **WHEN** sup_filedropdata 配置的删除 SQL 以 delete 开头
- **THEN** 不对其执行 DROP 或 CREATE，包括目标表不存在的情况；继续原有删除处理，失败按既有机制返回，不通过整表重建影响其他文件数据

#### Scenario: 大小写与空白
- **WHEN** 删除条件为 NULL、空串、纯空白、带前导空白的 TrUnCaTe 或 DELETE
- **THEN** 前四类进入重建，DELETE 跳过重建；其他非空前缀也跳过重建
