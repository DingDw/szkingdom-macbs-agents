## Purpose

为日终清算提供独立的文件全量导入能力，按配置选择文件，汇集当前业务域及配置路由的过滤所需数据并保留全部可解析源记录，通过可追踪的流程任务管理加载、导入、持久化和清理，支撑未导入数据分析。

## ADDED Requirements

### Requirement: 当前交付仅启用第一批次文件
系统 MUST 按已确认范围仅启用 `intfid=SHJS,fileid=SH_JSMX01` 的 SUP 全量导入；本期不扩展启用 `SH_JSMX02/03`，它们与 `SH_JSMX01` 的共表批次隔离不属于当前交付及验收范围。文件选择仍通过 `supflag` 配置驱动。

#### Scenario: 当前启用范围生成任务和文件树
- **WHEN** 按本期已确认配置生成 SUP 文件任务或查询 SUP 文件树
- **THEN** 仅包含启用的 `SHJS/SH_JSMX01`，不为 `SH_JSMX02/03` 生成导入和持久化任务，也不在 SUP 文件树中展示它们

### Requirement: SUP 样例初始化与运行实例识别分离
系统 MUST 仅将 `instid=9`、`instname=sup`、`partid=*`、`domainid=01`、`compute_node_num=1` 用作实例初始化样例；运行时按 `insttype=9` 及当前流程上下文选择实际实例，不得用上述样例值作业务校验；数据库连接地址和凭据由实施环境维护，增量脚本不得复制其他实例凭据或覆盖非 SUP 实例。

#### Scenario: 初始化固定表
- **WHEN** 使用 SUP 连接执行固定初始化入口
- **THEN** 仅建立 `sup_filedropdata`；忽略规则在 COMM 磁盘库维护，源表由动态持久化前处理创建

#### Scenario: 使用非样例 SUP 实例
- **WHEN** 当前流程业务域配置的实例类型为 9，但实例编号、名称、分区、业务域或节点数不同于初始化样例
- **THEN** 不因样例值不符而拒绝；任务参数、节点映射、持久化路由和释放范围均使用实际实例上下文

### Requirement: 全量导入按独立实例和文件开关运行
系统 MUST 使用类型为 `9` 的 SUP 实例承载分析数据，通过 `comm_if_file.supflag` 决定文件是否参加全量导入；该标志默认值为 `0`，只有值为 `1` 的文件进入本流程，常规实例的文件导入行为必须保持兼容。

#### Scenario: 仅导入启用文件
- **WHEN** 文件甲的全量导入标志为 `1`，文件乙为 `0`
- **THEN** 全量导入流程仅为文件甲生成导入和持久化任务，文件乙的常规处理不受影响

#### Scenario: 默认关闭功能
- **WHEN** 新增文件配置未显式启用全量导入
- **THEN** 该文件不参与全量导入，既有导入结果保持不变

#### Scenario: 标准初始化示例
- **WHEN** 执行标准路径下针对 `intfid=SHJS`、`fileid=SH_JSMX01` 的全量导入启用更新脚本
- **THEN** 该示例文件的 `supflag` 更新为 `1`，其他接口或文件的全量导入标志不受影响

### Requirement: SUP 流程任务在服务与节点应用可调度
系统 MUST 在 `macbs-service` 和 `macbs-node` 两个应用中提供 `supFlowPrepare`、`supFilePersist`、`supFlowCleanup` BEX 流程任务入口，使流程准备、单文件持久化和成功清理能够按流程配置执行，并将成功或失败结果返回流程引擎。

#### Scenario: 两个应用加载任务入口
- **WHEN** 分别部署包含 SUP 功能的 `macbs-service` 和 `macbs-node` 应用
- **THEN** 两个应用均能解析并调度上述 BEX 入口，不因缺少模块依赖或入口注册而无法执行流程任务

### Requirement: 独立流程提供四步骤和明确依赖
系统 MUST 提供无前置流程的 `9-文件全量导入` 流程，包含 `10-流程准备`、`20-文件导入`、`30-文件持久化`、`40-流程清理`；准备阶段动态产生文件任务，所有导入必须等待依赖数据加载成功，单文件持久化必须等待对应导入成功，清理必须等待全部持久化成功。

#### Scenario: 多文件依赖
- **WHEN** 同一流程分析两个文件且其中一个导入失败
- **THEN** 失败文件的持久化不得成功执行，流程不得标记全部完成，也不得通过正常清理抹去重试所需信息

#### Scenario: 未启用任何文件
- **WHEN** 准备阶段未发现需要全量导入的文件
- **THEN** 系统记录本次没有待处理文件，不产生虚假的文件任务，流程能够按空工作集正常结束

### Requirement: 流程只生成一个共享依赖加载任务
系统 MUST 在启用文件清单非空时，仅生成一个步骤 10 的 `660030` 加载任务及匹配实际 SUP 实例、节点的任务结果；任务编号为 `100100`，前置为当前 `supFlowPrepare`，参数包含 `cfg_group=sup` 和实际实例上下文，不绑定单个接口或文件。每个文件的导入任务 MUST 显式依赖该共享加载任务，持久化仍依赖对应导入。非空清单共生成 `1+2×文件数` 个动态任务及对应结果；空清单不生成动态加载、导入或持久化任务。

#### Scenario: 两个文件共享加载
- **WHEN** 准备阶段选择两个启用文件
- **THEN** 步骤 10 仅生成一个加载任务及一个结果，步骤 20 和 30 各生成两个任务及对应结果；两个导入的 `beforerecordno` 均为 `100100`，各持久化仅依赖对应导入

#### Scenario: 共享加载失败
- **WHEN** 唯一加载任务尚未成功或执行失败
- **THEN** 所有文件导入继续等待，不得因步骤激活而提前执行，也不得为其他文件再生成加载任务

#### Scenario: 从逐文件加载任务重做准备
- **WHEN** 本流程存在旧版 `100100～190099` 编号段内的多个 `660030` 动态任务及结果，当前启用文件清单非空
- **THEN** 准备重做删除这些旧任务及结果，仅重新生成一个 `100100` 加载任务并申请新的结果编号；保留已有 SUP 节点映射，不删除其他流程或模板任务

### Requirement: 计算节点分配及重试隔离
系统 MUST 从空闲计算节点中随机分配一个节点给本次 SUP 流程并保存实例映射；不得抢占正在使用的节点。同一次流程准备重试必须保留已分配 SUP 节点，删除本流程全部动态任务及对应任务结果后，按当前启用文件清单重新生成；不能复用旧任务图、重复占用节点或覆盖其他流程任务。节点选择沿用现有机制，不新增共享表锁或流程行锁。

#### Scenario: 没有空闲计算节点
- **WHEN** 准备时所有可用计算节点均已被占用
- **THEN** 准备任务失败并提示无空闲节点，不产生可运行的半套文件任务

#### Scenario: 准备任务重复执行
- **WHEN** 相同业务日期和流程执行上下文下重新执行准备任务
- **THEN** 保留已有 SUP 节点映射，删除旧动态任务及结果，再按当前启用清单生成唯一有效任务链和新的结果编号；模板准备、占位、清理任务定义与其他流程不被删除；后续步骤和占位、清理模板状态重置，等待本次执行

#### Scenario: 准备事务失败
- **WHEN** 删除旧动态任务后重新生成任务发生异常
- **THEN** COMM 事务回滚任务及映射变更；不新增共享表锁或流程行锁，不修改普通流程节点分配行为

#### Scenario: 重做后启用清单为空
- **WHEN** 原流程有动态任务，用户关闭所有文件后重做准备
- **THEN** 旧动态任务、结果及引用的临时配置被清除，不生成加载、导入或持久化任务；已有节点留待成功清理释放，没有已有节点则不新分配

### Requirement: 过滤依赖按配置及当前业务域加载
系统 MUST 精确匹配 cfg_group=sup、启用标志及目标实例类型，从配置决定加载表，不限定七张表或固定表数；类型 1 数据仅遍历 domainid 等于当前 GetDomainid() 的全部实例，其他类型保持通用路由。系统 MUST 复用通用全表、SQL、空表及分段加载能力；任一配置表加载失败均阻断后续导入；批次直接沿用通用插入或更新写入，不增加 SUP 专用主键去重、内容比较或冲突报错。

#### Scenario: 所需数据仅存在于另一个节点
- **WHEN** 已配置的必要源数据仅存在于当前业务域另一个类型为 `1` 的实例
- **THEN** 加载结果包含该实例数据供字段转换或适用逻辑使用，不将账户是否匹配作为 SUP 直接通过方式的附加条件

#### Scenario: 某个实例不可访问
- **WHEN** 任一必要源实例的过滤依赖数据加载失败
- **THEN** 加载任务失败，文件导入任务不得开始，错误信息能够定位源实例和表

### Requirement: 不增加基础数据就绪判定
系统 MUST 保持全量导入流程无前置流程，本期不增加席位、证券等基础数据的就绪检查、业务完整性检查或等待机制，也不要求额外提供外部就绪保证作为实施及验收前置条件。分析使用本次实际加载取得的数据；加载调用本身的异常或失败仍沿用现有任务失败处理。

#### Scenario: 正常加载得到空的基础表
- **WHEN** 基础数据加载调用成功，但席位或证券等基础表为空
- **THEN** 不新增就绪错误或等待步骤，继续按已确认的 SUP 过滤规则处理记录

### Requirement: 全量导入保留过滤未通过的记录
系统 MUST 按 SUP 专用策略执行支持的过滤规则评估，同时保留过滤通过和未通过、且满足记录身份约束的全部可解析源记录；正常业务过滤不通过不得使记录在预过滤、正式过滤或批量写入前丢失。启用规则含 `1/6/4` 时必须报告不支持全量转入并使文件任务失败，不得作为正常过滤丢弃继续处理。记录编号沿用解析后对象的 `id` 属性，支持 `int/bigint`；缺少该属性或类型不符时必须明确报告无法处理，不能另行生成编号掩盖问题。文件解析错误、缺失必要字段或写入错误不得伪装成业务过滤成功。

#### Scenario: 预过滤命中丢弃
- **WHEN** 一条满足记录身份约束的可解析记录在普通导入的预过滤阶段会被排除
- **THEN** SUP 导入仍保留该记录，并按 SUP 专用规则重新得到分析结论，只有 SUP 规则不通过时才生成丢弃记录

#### Scenario: 源文件损坏
- **WHEN** 文件内容不能按配置解析
- **THEN** 导入任务报告失败，不能将该文件标记为完整导入或持久化完成

#### Scenario: 解析对象不满足记录身份约束
- **WHEN** 解析后对象没有 `id` 属性，或其类型不是 `int/bigint`
- **THEN** 导入任务明确报错，不生成替代编号，不将该文件标记为完整导入

### Requirement: 成功清理释放本流程资源
系统 MUST 在全部文件成功持久化后，由 Java `supFlowCleanup` 直接删除本流程任务参数引用的持久化配置组及本流程类型为 `9` 的 SUP 节点映射，两类删除在同一 COMM 事务内依次完成。系统 MUST 保留持久化任务及结果完成检查和业务日期核对，不调用 C++ 清理功能，不删除内存数据、磁盘分析结果、任务结果及日志；异常恢复清理必须限定在本流程范围。

#### Scenario: 流程完成后查询
- **WHEN** 文件全部持久化成功并完成流程清理
- **THEN** 节点能够被重新分配，已持久化分析结果仍可按业务日期查询

#### Scenario: 成功清理的具体范围
- **WHEN** 本流程当前业务日期的全部持久化任务及结果已经完成，执行 `supFlowCleanup`
- **THEN** Java 先删除本流程引用的持久化配置组，再删除本流程 SUP 映射；不发起计算节点或 C++ 调用，其他流程及非 SUP 映射保留，内存数据、磁盘结果及执行状态均不删除

#### Scenario: 持久化尚未完成
- **WHEN** 本流程存在未完成、失败、业务日期不符或缺少成功结果的持久化任务，包括尚未激活的任务
- **THEN** 清理任务失败，不删除配置组或节点映射

#### Scenario: 删除配置或映射失败
- **WHEN** COMM 删除持久化配置组或任一 SUP 映射发生异常
- **THEN** 返回任务失败，不执行后续释放，事务回滚已经执行的配置及映射删除，保留重做上下文

#### Scenario: 空清单或重复清理
- **WHEN** 没有待执行的持久化任务，或本流程配置及 SUP 映射已成功删除后再次清理
- **THEN** 可正常结束，不因没有待删记录报错，不修改其他流程资源，也不发起内存库清理


### Requirement: 跨步骤任务按前置任务激活
系统 MUST 将新动态任务及结果的 runflag 初始化为 0，并采用前置任务激活方式，允许跨步骤依赖绕过步骤自身激活条件；唯一共享加载任务作为全部导入的显式前置，保证加载成功后才导入，持久化仅等待对应文件导入成功。

#### Scenario: 步骤尚未激活但文件前置完成
- **WHEN** 唯一共享加载任务已经成功，而导入步骤尚未激活
- **THEN** 导入任务可以被前置任务驱动；共享加载未成功时不得提前导入，清理仍等待全部持久化


### Requirement: 账户映射使用取模分段和四字段投影
系统 MUST 在配置要求加载 comm_accountmapped 时复用通用 settgroup 取模分段，覆盖完整余数集合；源 SQL 只返回 market、secuid、fundacct、settunit，settgroup 仅参与过滤谓词。读取适配不得把投影恢复为全字段，模型其他属性使用默认值；不为未读取字段补查数据库，不增加投影后的主键冲突处理。账户映射实际加载仅接受全表配置，内部生成四字段取模 SQL；外部 SQL 加载方式明确报错。空表加载方式仍只清表。

#### Scenario: 多实例账户映射四字段加载
- **WHEN** 配置加载账户映射，当前业务域多个类型 1 实例存在待加载数据
- **THEN** 每个实例完整覆盖全部取模余数，实际返回列只有指定四列，目标保留这四个字段值，未读取字段为默认值，写入沿用通用行为，不额外比较或去重投影记录

#### Scenario: 配置表超出原七表
- **WHEN** sup 配置增加已注册通用管理器的其他表，或关闭原示例中的表
- **THEN** 按配置加载，不因表名不在原七表清单或表数不等于七而拒绝；未配置及关闭的表不读取、不清空

#### Scenario: 同类型实例属于其他业务域
- **WHEN** 其他业务域存在类型 1 实例，包括不可访问的实例
- **THEN** 不读取该实例，不将其数据合入当前 SUP，也不因它不可访问而失败

#### Scenario: 配置 SQL 或空表方式
- **WHEN** 配置表分别使用带条件 SQL 或空表加载方式
- **THEN** SQL 表按通用条件和分段读取，空表方式仅清空配置目标表，不发起该表数据读取

### Requirement: 多实例加载不增加专用主键冲突处理
系统 MUST 将已读取批次经 m_ProcessQueue 交由通用 WriteDataToMemdb 写入，沿用批量插入及失败后插入或更新策略，不保留 SUP 专用主键索引、逐字段比较、去重或同键异值报错。底层加载及写入失败仍按现有失败机制处理，不作为成功忽略。

#### Scenario: 多实例或批次含相同主键
- **WHEN** 不同源实例或批次读取到主键相同的记录
- **THEN** 直接沿用通用写入行为，不产生 SUP 专用冲突错误，不保证额外的确定性冲突选择规则

#### Scenario: 账户映射使用全表配置
- **WHEN** 账户映射配置为全表加载
- **THEN** SUP 内部转换为四字段取模 SQL，再使用通用分段；配置为 SQL 方式时明确拒绝，空表方式仅清表


### Requirement: SUP 复用通用加载双队列线程模型
系统 MUST 继承 CAsyncMemdbSync 并复用 AsyncLoad 的准备线程、m_PrepareQueue、读取调度及 CJstpThreadPool、m_ProcessQueue 和独立写入线程；准备回调不得同步执行数据读取或内存写入。threadnum、prepare_queue_size、process_queue_size、timeout MUST 作用于同一通用驱动，复用背压、完成通知、异常及超时处理。通用加载入口的默认行为保持。

#### Scenario: 准备读取写入并行流水线
- **WHEN** 多个分段待加载，threadnum 大于 1
- **THEN** 分段通过准备队列进入读取线程池，读取结果通过写入队列由独立写入线程处理，准备线程可继续生成后续分段；所有写入完成后共享加载才成功

#### Scenario: 不同源实例任务交错执行
- **WHEN** 当前域多个源实例的分段同时排队或读取
- **THEN** 每个任务使用入队时复制的源实例，统计和读取来自同一来源，准备线程切换来源不会使旧任务切错库，其他业务域不参与

#### Scenario: 队列背压与异常退出
- **WHEN** 准备或写入队列已满，或者任一阶段发生异常或超时
- **THEN** 复用通用队列等待、退出标记和线程汇总机制；失败或超时不得返回共享加载成功，保留通用活动任务诊断，不新增强制取消已提交任务的行为

#### Scenario: 空配置和空表方式
- **WHEN** 没有启用配置，或者配置均为空表方式
- **THEN** 无启用配置直接结束；空表方式只清理对应目标表，不生成读取任务，队列正常结束


### Requirement: 加载表管理器扩展点不遮蔽既有工厂
通用异步加载和 SUP 子类 MUST 使用 CreateLoadTableManager 作为读取表管理器创建扩展点，同步声明、实现及调用；不得以同名成员 CreateLoadManager 隐藏既有全局工厂，跨版本检查继续取得 ILoadManager 类型的工厂实例。

#### Scenario: 跨版本检查创建加载工厂
- **WHEN** CCheckMemdbSync::Before 调用 CreateLoadManager(m_szFactoryName)
- **THEN** 调用原全局工厂并返回 ILoadManager*，不解析为返回 shared_ptr<CMacbsMemdbManagerBase> 的异步加载成员；SUP 字段投影仍经新名称的虚函数派发
