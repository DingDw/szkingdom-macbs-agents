## 忽略规则和重跑

1. 保持 MemDB 中不存在 `sup_filedropignorerule`，在 COMM 磁盘配置 `xwh in ('1','2') and zjzh = '123'`；命中任一规则的丢弃行置忽略标志，但保留丢弃行。
2. 分别验证无规则、跨接口/文件、等值、AND、引号转义、未知字段及非法表达式。非法规则在 Cache 阶段报错，原连接恢复。
3. 成功后修改/删除规则，再重跑全量导入。在 Before 中删除当前 intfid+fileid+busidate 的旧丢弃行；预置同 fileid 不同 intfid、不同 fileid 及不同 busidate 的隔离记录，确认均保留。
4. 将丢弃行改为通过、减少文件行数、使用合法空文件，确认内存和磁盘均不残留当前三条件范围旧结果。检查 Before 返回时删除已完成；同主键重跑时只写入本次读取批次，不再使用共享结果缓存、前缀或在 Write 重复写回。
5. 注入 Before 删除失败，确认功能号失败且不进入规则加载和解析；普通实例、SUP 导出及直接入磁盘均不执行该清理。在重跑解析途中注入失败，确认旧 persiststatus 已失效，查询不能开放旧成功结果。仅重试持久化时，不重新读取和执行忽略规则。

## 通用双队列线程模型

- 设置 threadnum=2，准备多个读取耗时不同的分段，核对读取并发和准备、读取、写入三阶段重叠；准备回调没有直接读写，全部写入结束后功能号才成功。
- 设置 prepare_queue_size=1、process_queue_size=1，分别延迟读取和写入；核对队列产生背压，恢复后分段完整消费，没有丢批次或重复清表。
- 当前域两个源实例各放置对方没有的数据，使第一实例任务排队时准备线程已转向第二实例；核对任务记录的来源及实际 SQL 连接一致。重复批次号不得造成来源混淆，其他域不可访问实例不得影响加载。
- 分别使统计分段、数据读取、内存写入失败，确认异常汇总到共享加载且阻断全部导入；分别延迟各阶段触发 timeout，核对通用退出等待及活动读取任务诊断，不能在后台尚有本次写入时返回成功。
- 核对空配置直接结束、仅空表配置不读取、账户全表配置仍覆盖全部取模余数且只读四字段；队列容量及 timeout 非正时在线程启动前拒绝。
- 普通 600000 入口使用相同配置回归：默认分段方式、路由、管理器及队列写入策略保持；SUP 660030 仍使用原有入口注册。运行用例待任务 7.4 授权执行。
