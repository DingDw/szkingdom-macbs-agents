模式 2：全日成交量区间

policyid=2 / TDDRG_MARK 先按资金账号、币种、策略品种汇总全市场折算成交金额，再用该总量为每笔流水选择费率。

输入与来源

数据项来源说明
策略启用信息fee_jzjy_policy_fundinfo.policyid='2'、serverid/orgid/fundid/policykind。只处理已配置全日成交量策略的资金账号。
可统计业务范围comm_busidefine.policy_fee_stat_flag='1'。只有参与策略佣金统计的业务类别才进入全日总量。
匹配上下文公共数据准备中的普通佣金等价匹配上下文。用于判断该笔流水是否落入策略区间适用范围。
全日控制值node_settdetail.matchamt + fee_jzjy_policy_stkscale.stkscale。按 key orgid|fundacct|moneytype|policykind 汇总折算成交金额。
区间费率fee_jzjy_policy_type。使用全日控制值命中 ctrlvalue/feerate/minfee/maxfee。

算法

  1. 遍历待处理流水，筛选 policyid=2 且 policy_fee_stat_flag='1' 的流水。
  2. 构造普通佣金等价匹配上下文；如果没有任何策略区间覆盖该流水范围，则该笔不计入全日总量。
  3. 计算折算成交金额：foldMatchAmt = abs(matchamt) * stkscale，未配置有效权重时使用 abs(matchamt)。
  4. 按 orgid|fundacct|moneytype|policykind 汇总得到 dayTotalFoldMatchAmt。
  5. 逐笔处理时，以 dayTotalFoldMatchAmt 为控制值，在 fee_jzjy_policy_type 中查找命中区间。
  6. 候选策略佣金：policyFee = ApplyMinMax(abs(matchamt) * feerate, minfee, maxfee)。
控制值 = sum(abs(node_settdetail.matchamt) * fee_jzjy_policy_stkscale.stkscale) 分组键 = node_settdetail.orgid + node_settdetail.fundacct + 匹配币种 + fee_jzjy_policy_fundinfo.policykind 候选佣金 = min/max 裁剪(abs(node_settdetail.matchamt) * fee_jzjy_policy_type.feerate)

policyid=3 / ALTRD_MARK 维护客户周期累计成交金额。本笔成交会跨越一个或多个区间时，按区间分段分别套费率后合计。

输入与来源

数据项来源说明
策略启用信息fee_jzjy_policy_fundinfo.policyid='3'、serverid/orgid/fundid/policykind。确定资金账号采用累计成交量策略。
可统计业务范围comm_busidefine.policy_fee_stat_flag='1'。未开启统计的业务类别不进入累计策略。
统计周期配置fee_jzjy_policy_stat.busidate/serverid/sno/orgid/policyid/policykind/moneytype/pt_*/cycleflag/cyclevalue/begindate。按普通佣金等价上下文匹配统计配置，取得 sno 与周期开始日。
客户累计状态fee_jzjy_policy_cusstatmy.busidate/serverid/orgid/fundacct/moneytype/policyid/policykind/sno/totmatchamt/totmatchamttmp/totfee/totfeetmp/prvtotmatchamt。当日无记录时从上一日同主键记录承接；若 fee_jzjy_policy_stat.begindate=busidate，则新周期从 0 开始。
区间费率fee_jzjy_policy_type.ctrlvalue/feerate/minfee/maxfee。分段计费时按控制值升序组织区间。

算法

  1. 匹配 fee_jzjy_policy_stat，取得统计 sno 和周期信息。
  2. 按主键 busidate, serverid, fundacct, moneytype, sno, orgid, policyid, policykind 获取或创建当日 fee_jzjy_policy_cusstatmy。
  3. 设置本笔累计起点 begin = cusstatmy.totmatchamttmp，终点 end = begin + foldMatchAmt。
  4. 收集适用的 fee_jzjy_policy_type 区间，按 ctrlvalue 升序排列。
  5. 从 begin + 0.01 所在区间开始，循环切分到下一档控制值或 end。
  6. 每段折算成交金额 sectionFold = sectionEnd - cursor；还原本笔实际成交金额份额 sectionMatchAmt = abs(matchamt) * sectionFold / (end - begin)。
  7. 每段费用 sectionMatchAmt * 当前区间费率，各段相加后按最后命中区间的 minfee/maxfee 做裁剪。
  8. 更新 cusstatmy.totmatchamttmp/totmatchamt=end，并将候选佣金累加到 totfeetmp/totfee。
begin = fee_jzjy_policy_cusstatmy.totmatchamttmp end = begin + 折算成交金额 sectionMatchAmt = abs(node_settdetail.matchamt) * (sectionEnd - cursor) / (end - begin) 候选佣金 = min/max 裁剪(sum(sectionMatchAmt * section.feerate))

数据项来源说明
策略启用信息fee_jzjy_policy_fundinfo.policyid='4'、serverid/orgid/fundid/policykind。确定资金账号采用累进成交量策略。
可统计业务范围comm_busidefine.policy_fee_stat_flag='1'。未开启统计的业务类别不进入累进策略。
统计周期配置fee_jzjy_policy_stat。用于取得统计 sno 并创建/承接客户累计统计。
上一周期累计控制值fee_jzjy_policy_cusstatmy.prvtotmatchamt。创建当日统计记录时，从上一日同主键 totmatchamt 写入；若新周期从 0 开始，当前累计值重置但 prvtotmatchamt 保留为上期累计参考。

  2. 控制值取 cusstatmy.prvtotmatchamt，即上一周期累计成交金额。

  5. 无论是否命中区间，都会将本笔折算成交金额累加到 cusstatmy.totmatchamttmp 并同步 totmatchamt；命中时再累加 totfeetmp/totfee。
控制值 = fee_jzjy_policy_cusstatmy.prvtotmatchamt 候选佣金 = min/max 裁剪(abs(node_settdetail.matchamt) * fee_jzjy_policy_type.feerate) 统计更新 = totmatchamttmp + 折算成交金额

模式 5：资产量区间

policyid=5 / ASSRG_MARK 使用订单下场资金资产和股份市值合计作为控制值。该模式不依赖 comm_busidefine.policy_fee_stat_flag 过滤业务统计范围。

输入与来源

数据项来源说明
策略启用信息fee_jzjy_policy_fundinfo.policyid='5'、serverid/orgid/fundid/policykind。确定资金账号采用资产量区间策略。
资金资产intf_order_fundasset.fundid/moneytype/fundbal/fundbuysale/funduncomebuy/funduncomesale。按 fundid=ToInt64(fundacct) 和匹配币种查询；无资金资产记录时报错，不能按 0 处理。
股份资产数量intf_order_stkasset.fundid/moneytype/market/stkcode/stkbal/stkbuysale/stkuncomebuy/stkuncomesale。数量口径：stkbal + stkbuysale + stkuncomebuy - stkuncomesale；数量为 0 的记录跳过。
证券与市值comm_stock.market/stkcode/stkid、comm_stkprice、comm_marketcurcode、comm_exchangerate，通过 CMarketValueUtil::GetMarketValue 计算。找不到证券或汇率时报错；找不到行情时记录告警并使用市值工具返回值。面值兜底参数来自 PARAMID_MKTVALUE_CALAC_WITH_TICKPRICE_SWITCH 和 PARAMID_MKTVALUE_CALAC_WITH_TICKPRICE_FUNDKIND。
区间费率fee_jzjy_policy_type.ctrlvalue/feerate/minfee/maxfee。用资产量合计作为控制值命中区间。

算法

  1. 按资金账号和币种读取 intf_order_fundasset，资金资产合计为 fundbal + fundbuysale - funduncomebuy + funduncomesale。
  2. 按资金账号和币种读取 intf_order_stkasset，逐条计算股份数量。
  3. 对每条非零股份数量，按市场和证券代码读取 comm_stock，再通过市值工具结合行情、市场币种和汇率计算市值。
  4. 资产量控制值 assetAmt = 资金资产合计 + 股份市值合计。
  5. 在 fee_jzjy_policy_type 中按 assetAmt 命中区间。
  6. 候选策略佣金：policyFee = ApplyMinMax(abs(matchamt) * feerate, minfee, maxfee)。
资金资产 = sum(fundbal + fundbuysale - funduncomebuy + funduncomesale) 股份数量 = stkbal + stkbuysale + stkuncomebuy - stkuncomesale 资产量 = 资金资产 + sum(CMarketValueUtil::GetMarketValue(stkid, busidate, 股份数量)) 候选佣金 = min/max 裁剪(abs(node_settdetail.matchamt) * fee_jzjy_policy_type.feerate)

佣金优先标志优先取 fee_jzjy_orgpriorflag.serverid/orgid/feepriorflag；未配置时回退混合参数 PARAMID_JZJY_YJYXBZ。2-动态佣金优先 时用策略佣金；0-最低优先 时取原手续费与策略佣金绝对值较小者；其他值保留原手续费。

优惠券抵扣fee_jzjy_policy_cusothval，当日数据由上一日或 busidate=0 记录生成。当前代码实现会对净佣金应用优惠券抵扣，并更新可用余额。若按需求文字“暂不处理优惠券抵扣”验收，可将此项视为当前代码后续增强。
费用备注node_settdetail.fee_remark。追加 策略佣金[类型;序号;控制值;费率;资产量;策略佣金;优惠券;最终手续费;净佣金;优先标志]，不覆盖原普通佣金备注。
清算金额重算comm_busidefine.clearamt_valueexplain 与 node_settdetailsub 修正后费用字段。策略修正后按业务定义表达式重算 node_settdetail.clearamt 并写回子表 clearamt。

总决策公式

signedPolicyFee = 原手续费为负 ? -abs(候选策略佣金) : abs(候选策略佣金) if 佣金优先标志 == 动态佣金优先: finalSeat = signedPolicyFee else if 佣金优先标志 == 最低优先: finalSeat = abs(原手续费) > abs(signedPolicyFee) ? signedPolicyFee : 原手续费 else: finalSeat = 原手续费 if 手续费小于模式 == 按一级费用兜底 and abs(finalSeat) < 一级费用合计: finalSeat = 原手续费方向对应的 +/- 一级费用合计 finalYjf = finalSeat 扣除一级费用后的净佣金 finalYjf = 应用优惠券抵扣后的净佣金 finalSeat = finalYjf 加回一级费用后的总手续费

重做恢复口径

  1. 恢复功能只在重做标志开启时执行。
  2. 按当日交割流水和流程市场范围扫描 node_settdetail。
  3. 若 node_settdetailsub 存在 fee_seat_old，表示该流水已被策略佣金修正，需要恢复。
  4. 将 fee_seat_old/fee_yjf_old/clearamt_old 回写到 fee_seat/fee_yjf/clearamt，删除本次策略佣金追加的 fee_remark 摘要。
  5. 删除旧值备份字段 fee_seat_old/fee_yjf_old/clearamt_old，避免下次处理误判。
  6. 删除当日 fee_jzjy_policy_cusstatmy 和当日优惠券记录，处理功能再从上一日数据重新生成。
