📋 node_gdkhdz 股东客户对照表 — 生成逻辑分析

模块：新意报表（report） 业务对象：607040100 导出接口：XY_GDKHDZ / XY_GDKHDZ_RPT 主类：GdkhdzHandler / GdkhdzTask

node_gdkhdz（股东客户对照信息）是供新意报表导出的数据源表，存储"股东账户 — 资金账户 — 银行/存管 — 营业部/席位"的对照关系。生成过程将 MACBS 内部的 node_secuid（股东账户）、node_fundacct_bank（资金账号银行信息）、 node_fundacct（资金账户）三张表的数据，按新意格式规范进行编码转换后落库，供 C++ 批量导出流程 BATCH_FILE_IMP_EXP_OUT_FLOW 导出为新意股东客户对照文件。

3.1 核心查询 SQL（selectGdkhdzEntity）

select rownum as rn,
       t.market                    jypz,   -- 交易品种（先取市场代码，后按配置转换）
       ' '                         jgdm,   -- 机构代码：固定空格
       nvl(nf.orgid, t.orgid)      yybdm,  -- 营业部编码：资金账户orgid优先，缺省取股东表orgid
       (zdxwType='1' ? t.mainseat : t.trdseat) zdxw, -- 席位：参数67057，0交易席位/1托管席位
       t.secuid                    gdzh,   -- 股东账户
       t.fundacct                  zjzh,   -- 券商资金账户
       ' '                         cgfs,   -- 存管标志（占位，后续转换）
       t.status                    zhzt,   -- 客户状态（后续按配置转换）
       nvl(b.bankcode, ' ')        yhdm,   -- 银行代码（后续转换）
       t.open_date                 jyzh,   -- 交易账号：借用存放开户日期（后续清空）
       t.ext_cls                   extCls, -- 外部类别：区分H股股东
       nf.curcode                  curcode -- 币种（H股拆分/交易品种特判用）
from node_secuid t
  left join (select * from node_fundacct_bank nb
             where nb.status in ('0','1','4')) b
    on (t.fundacct = b.fundacct
        and (case when t.market='2' then '1'   -- 深B → 港币
                  when t.market='3' then '2'   -- 沪B → 美元
                  else '0' end) = b.curcode)
  left join node_fundacct nf on t.fundacct = nf.fundacct
where t.status != '9'                          -- 排除销户状态
  and t.open_date <= #{busidate}              -- 已开户
  and t.secuid between #{startSecuid} and #{endSecuid} -- 按股东代码区间分批

4.2 H股多币种拆分（processNodeGdkhdzs）

  • 触发条件：市场=深B（'2'）且 ext_cls = 'H'（H股全流通账户，字典 613008）且币种 curcode 含逗号（多币种）。
  • 规则：按逗号拆分币种，为每一个币种复制生成一条新记录（其余字段完全相同，仅 curcode 不同），并删除原多币种记录。
  • 目的：同一 H 股股东账户可能同时对应人民币/港币多条银行关系，拆分后每个币种对应一条对照记录；配合后续交易品种特判（HCHK/HCGF），保证新意文件每个币种一行。
  • 币种为空时跳过（记录日志），不产生数据。

4.3 去重规则

转换完成后按联合主键 6 字段 (jgdm, yybdm, jypz, zdxw, gdzh, zjzh) 做 Collectors.toMap 去重，保留先出现的记录，丢弃后出现的重复记录（merge 函数保留 existing）。

⚠️ 需求背景（FS-CBS-13424）：股转/京A 与沪A 等市场可共用同一资金账户，若出现主键完全相同的记录，改用 batchInsert 直接插入会导致主键冲突，因此在落库前先按主键去重。

六、并发处理模型

flowchart TD subgraph POOL1["线程池1（生成）：n = threadNum/2（至少2）"] G1["任务: createGdkhdz(实例, 映射..., 起止secuid)"] G2["按 secuid 排序数组分片
perProcsize 默认100000"] end subgraph POOL2["线程池2（落库）：n = threadNum/2"] S1["任务: SaveGdkhdz(实例, List)"] S2["Lists.partition 每批 1 万条"] S3["内部再开线程池
batchInsert 并发插入"] end N["节点实例循环（串行）"] --> TR["truncate node_gdkhdz"] TR --> POOL1 POOL1 --> F["Future 收集结果"] F --> POOL2 POOL2 --> W["等待保存完成"]
  • 实例级：按结算主体的计算节点实例串行处理；每个实例先 truncate 清空再生成。
  • 批次级：全量股东代码排序后按 perProcsize（参数，默认 100000，手动入口固定 100000）切分区间，提交线程池并发生成。
  • 生成线程数：threadNum 参数 ÷ 2（下限 2）。
  • 落库：每个实例返回的列表按 1 万条一批 partition，每批再开一个线程（线程数 = 批数）执行 batchInsert。
  • 排他性：手动重新生成前必须校验无正在运行的清算流程（RegenerateCheck.checkExistsRunningFlow），避免 truncate 正在被清算读取的数据。
  • 失败处理：任何一步异常 → 标记失败，最终抛 BASEERR_CODE_103018486（"生成股东客户对照失败，详情查看日志"）。
